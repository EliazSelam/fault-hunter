# Fault Hunter: context for a new session

## What this is
The public version of Eliaz's interactive learning system for electro-mechanical and optical machines ("מהרכיב למכונה"), from a resistor to AOI and AOS machines for PCB manufacturing. MIT licensed, published on GitHub Pages.

- Answer the user in Hebrew. UI text is Hebrew, technical terms in English. Repo docs and code comments are in English.
- Repo: https://github.com/EliazSelam/fault-hunter (public), branch `main`. Site: https://eliazselam.github.io/fault-hunter/
- **Public content only.** Nothing that identifies a specific employer, job opening or interview preparation, and no product names of a specific equipment maker. That material lives in a separate private repository and must not be copied here. Typical figures are described as "typical, from public manufacturer specifications".

## What the user expects
- **Teacher level, assume nothing.** Explain mechanisms, not labels. Every term a lesson uses is defined in that lesson.
- **Principles over memorization, interactive over text.** Prefer a simulation, a hint or a question to another paragraph.
- **Everything correct and validated.** A wrong number is worse than a missing one. Run the `fh-validate` skill (`.claude/skills/fh-validate/`) or `tests/run_all.sh` before any commit or publish, and quote the result.

## Architecture
- `src/` is concatenated by `build.sh`, in the order listed there, into one self-contained `index.html` (one `<script>`; all globals). A new file must be added to `build.sh`.
- Key globals: `COMPONENTS`, `SYSTEMS`, `SYSX`, `SCN` (48 faults), `QB` (112 questions), `QT` (question topics: every question's `t` must exist here), `VERIFY`, `LEX`, `PRINCIPLES` (12), `PRIN`, `go(sheet, arg)`.
- Some functions are reassigned in later files to add behaviour: `showS1`, `showSys`, `showInt`, `glossify`, `playScn`, `showQ`, `ansFig`. Read the later files before changing one.
- Hebrew and formulas: wrap text that contains formulas or units in `bidi()` (in `src/35-foundations.js`).
- Map of `src/`: 10–12 components (12 = repair laser and fiducials), 20 systems, faults in 30 + 38 + 39d + 50, questions in 39e + 39j + 50, 39i digital logic, 42 live figures (generated by `figures/embed.mjs` from `figures/*/build.mjs`; every figure needs a check in `tests/figures_audit.mjs`), 50 PCB/AOI/AOS tab and integration process, 51–55 from-zero lessons and lexicon, 56 motors tab, 57 machines and power conversion (extends the motors tab), 59 3D engine and simulations (view3, paint3; rotating field, backlash, scan head, laser crater, stepper), 66 process simulator (TOPICS: steps, quiz, fault trees, math; aoiScene), 65 navigation groups and site-wide search (wraps go, setTab, routeGo), 58 terms (definitions, TERM_LINK to the explaining page, the glossary tab, the inline pass), 60–63 lab and the 12 principles, 64 fault teaching layer.

## Topic rule
A topic in `src/66-topics.js` starts at the essence and widens: `punch` and `analogy`, then `steps` (3D, one lead element per step), `quiz`, `faults` (decision trees: every option leads to a node, leaves have `leaf`, `fix`, `pr`, optional `go`), and `math` (MathML via the `MM` helpers, numbers added to `VERIFY`). `tests/topics_audit.mjs` walks every leaf.

## Zoom
`src/77-zoom.js` (tab `zoom`, first under "getting started") is the system zoom, like "Powers of Ten": five scales (1 components, 2 small circuits, 3 mechanisms and principles, 4 systems working in parallel, 5 the process), each made of the one below. `ZOOM` lists the nodes; a node has a core window and windows around it, and `parts` (zoom in; the parents are derived for zoom out). A window is a unit that already exists in the project (lesson part via `zParts`, `formBox`, `bench`, a system bench, a live figure, a 3D sim, a topic scene, flow, derivation, fault tree, quiz, an atlas card, a motor window captured once by `zCapture`). Every window has exactly one home; several windows on one subject at different depths are fine, the same content twice is a duplicate. `tests/zoom_audit.mjs` checks homes, rendering, duplicate content, structure, navigation and authorship.

## The machine in 3D (main layer)
`src/79-machine3d.js`: the zoom tab opens on one complete inspection machine in 3D (`MPARTS`: each part is boxes, an explode direction and a zoom node). It assembles itself on open, explodes with a slider, turns, zooms, and a click flies to a part and lists its windows in two layers: layer 1 shows and simulates (`LAYER1` kinds), layer 2 explains. Node pages show layer 1 before layer 2. `INNER` (keyed by topic) holds inner assemblies: opening a part explodes it into the parts it is made of, recursively (`mOpen`, `mUp`, `MS.path`); every inner part must be the topic itself or a part of it in the zoom tree, and the zoom suite checks it. `ZAPPX` holds the topics that are not parts of the machine (production line, digital logic, measurement); they are appendices, not parts of anything.

## Continuity rules
Arrow keys belong to an activity when the focus is in it; the page's level navigation answers only from the page or its navigation (`81-polish.js`). A hub window's state (step, controls, animation step and parameters) is saved before it is replaced or the topic is left, and restored when it opens again (`winSave`/`winRestore` in `84-hub.js`). Animations run on a simulation clock that pause freezes. The topic object is still during an activity and turns only under the pointer or with the focus; it is a keyboard button with a visible button beside it. Visits are called visits ("ביקרת"), not understanding. Each finding from the external review (F01–F06, F08, F10) has its own behaviour check in the zoom suite.

## Layers of the site
`src/85-layers.js`: the views bar puts what a learner needs first (the machine, the world map, all simulations, the last topic, appendices) and tucks the method's proofs (tree, 3D layers, duplicates report) into "behind the scenes". The world map (`#/zoom/world`) shows each system as a continent and what it is made of as cities around it, sized by windows and filled when explored, above a row of statistics. Inside a hub, windows are grouped by subject and named by kind (or title when kinds repeat) through `hubAfterRender`; long text windows open as a summary first. More `ANIMS`: encoder quadrature, PWM ripple, cable drop, EtherCAT frame time, each checked against its model.

## A topic as an object with hubs
`src/84-hub.js`: a topic page shows the topic's own 3D object in the middle (`hubGeometry`: its inner parts exploded, its machine part, or the part it sits in) and six hubs around it (`HUBS`: demo and simulation, physics and math, reverse engineering and faults, what's inside, questions, reading), each window in exactly one hub by its kind (`hubOf`). A hub opens one window at a time, with pills to switch. No company or product names anywhere in the book or the repository notes.

## The physics and math layer, animated
`src/83-anim.js`: `ANIMS` holds animated derivations (a list of steps that each render their own numbers, a canvas `draw(ctx, W, H, P, V, step, time)` that shows what the current step says, and sliders). They are windows `anim:<id>` of their topics, first in the theory layer, and in the gallery. Their `calc` must use the model constants (LZ, VT/vacCalc, SV), and the zoom suite checks that they reproduce the models' numbers.

## Two machines and the gallery
`src/82-machines.js`: the machine view switches between the AOI machine, the AOS machine and the whole line (`MS.machine`; `MCTX` marks the heads; `mCopies` draws one machine, or both with the verification station between them). `zSimList()` lists every simulation, live figure and process scene by machine; the gallery (`#/zoom/sims`) opens any of them in place (`zOpenWindow`), and the machine finder finds them too.

## Nothing swallowed, easy to move, inviting
`src/81-polish.js`: every component lesson section and every topic's numbers-and-explanation is a window (`CSECT`, `t:X:eng`); `tests/sims_audit.mjs` instruments every interactive builder, opens all old pages, and fails if anything they used is not reachable from the zoom. Movement: a path bar from the machine down (`zMainPath`), siblings at the same scale (`zSiblings`), arrow keys (up out, down in, left/right siblings), a finder in the machine (`mJump` opens down to the part). Curiosity: explored topics (`fh-explored`), progress and the next topic to explore, a teaser question on hover (`zTeaser`). The machine is drawn with shaded faces, cylinders for round parts (`MSHAPE`, `ROUND`), a glow on hover and a floor shadow, on a dark stage in the palette's blues.

## The machine leads
The book opens on the machine (`go('zoom')` in 40-app when there is no address). The top bar has three groups: the machine, appendices (practice, principles, glossary, standards, interview), about. Every other tab is still a page, reached from inside the machine (windows, back bars, search), not from the top bar. `src/80-integrate.js`: the servo drive holds the control loop; `mReach()` must find every non-appendix topic as a machine part or inside an opened part.

## Zoom views and about
`src/78-zoom-views.js`: inside the zoom tab, a views bar (zoom · tree by scale · 3D stack · duplicates report). `zCoverage()` accounts for every existing page (in the tree, the same content under another address, or a shared resource in `ZRES`); `zDupCheck()` is the live duplicates check. `ZCORE` marks the core chain of each scale, `ZCTX` the AOI/AOS-only topics. Tab `about`: the project and its author, with LinkedIn and GitHub buttons (GitHub only there).

## Master map
`MASTER` in `src/73-master-map.js` places every asset on a level of its subject's cone (16 subjects in 3 tracks, plus shared resources; 8 levels from essence to integration). `tests/master_map.mjs` fails if any page, system stage, topic level, simulation, figure, CircuitJS circuit, question or fault is unplaced, or if a ref points at nothing, and writes `docs/MASTER_MAP.md`. Data only for now: the interface does not read it yet.

## One home per subject
A subject covered in several tabs has one entry: its simulator topic. `SUBJECTS` in `src/72-subjects.js` lists every other page about it with what that page adds; those pages get a subject bar (part of «X», what this page adds, the way to the showcase, the other pages), and the topic lists them all. Optics pages that repeat a component page are listed in `ROUTE_ALIAS` and say so. A new page about an existing subject goes into `SUBJECTS`, not into a new tab.

## Structure rule
Every topic has an `ARCH` entry in `src/70-structure.js`: `why`, `f3` (CEO, architect, engineer), `blocks` (int, if = interface, ext = other system, with x, y), `flows` (from, to, signal kind e/d/m/o/p, label, the steps where it is active), and `rev` (for every block: what breaks, the first failing step, and an optional simulation preset). Every step must have an active flow and every block a flow; `tests/topics_audit.mjs` checks it.

## Learning model rule
Every topic follows the levels in `src/67-topic-levels.js`: map (where in the machine), essence (steps with `pred` predictions), intuition (`quiz`), engineering depth (`explain` self-explanation), faults (each with `solo` observations and its answer leaf, shown worked, guided and on your own), math (optional), integration (`integ`, linking other topics), and review. Each of see, eng and math ends with a `checks` question. Answers feed a Leitner review queue in localStorage (1, 3, 7, 21 days), interleaved across topics.

## Terms rule
Every new English term must be defined (in `TERM_NEW` in `src/58-terms.js`, or in `LEX`), and given a `TERM_LINK` to the page that explains it if there is one. `tests/terms_audit.mjs` fails on any undefined term. English sentences (interview lines, machine messages) get `lang="en"` so they are not glossed.
