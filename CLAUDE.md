# Fault Hunter: context for a new session

## What this is
The public version of Eliaz's interactive learning system for electro-mechanical and optical machines ("מהרכיב למכונה"), from a resistor to AOI and AOS machines for PCB manufacturing. MIT licensed, published on GitHub Pages.

- Answer the user in Hebrew. UI text is Hebrew, technical terms in English. Repo docs and code comments are in English.
- Repo: https://github.com/EliazSelam/fault-hunter (public), branch `main`. Site: https://eliazselam.github.io/fault-hunter/
- **Public content only.** Nothing that identifies a specific employer, job opening or interview preparation, and no product names of a specific equipment maker. That material lives in a separate private repository and must not be copied here. Typical figures are described as "typical, from public manufacturer specifications".

## What the user expects
- **Teacher level, assume nothing.** Explain mechanisms, not labels. Every term a lesson uses is defined in that lesson.
- **Principles over memorization, interactive over text.** Prefer a simulation, a hint or a question to another paragraph.
- **Everything correct and validated.** A wrong number is worse than a missing one. Run the `fh-validate` skill (`.claude/skills/fh-validate/`) or `tests/run_all.sh` before any commit or publish, and quote the result.

## Architecture
- `src/` is concatenated by `build.sh`, in the order listed there, into one self-contained `index.html` (one `<script>`; all globals). A new file must be added to `build.sh`.
- Key globals: `COMPONENTS`, `SYSTEMS`, `SYSX`, `SCN` (48 faults), `QB` (112 questions), `QT` (question topics: every question's `t` must exist here), `VERIFY`, `LEX`, `PRINCIPLES` (12), `PRIN`, `go(sheet, arg)`.
- Some functions are reassigned in later files to add behaviour: `showS1`, `showSys`, `showInt`, `glossify`, `playScn`, `showQ`, `ansFig`. Read the later files before changing one.
- Hebrew and formulas: wrap text that contains formulas or units in `bidi()` (in `src/35-foundations.js`).
- Map of `src/`: 10–12 components (12 = repair laser and fiducials), 20 systems, faults in 30 + 38 + 39d + 50, questions in 39e + 39j + 50, 39i digital logic, 42 live figures (generated by `figures/embed.mjs` from `figures/*/build.mjs`; every figure needs a check in `tests/figures_audit.mjs`), 50 PCB/AOI/AOS tab and integration process, 51–55 from-zero lessons and lexicon, 56 motors tab, 57 machines and power conversion (extends the motors tab), 59 3D engine and simulations (view3, paint3; rotating field, backlash, scan head, laser crater, stepper), 66 process simulator (TOPICS: steps, quiz, fault trees, math; aoiScene), 65 navigation groups and site-wide search (wraps go, setTab, routeGo), 58 terms (definitions, TERM_LINK to the explaining page, the glossary tab, the inline pass), 60–63 lab and the 12 principles, 64 fault teaching layer.

## Topic rule
A topic in `src/66-topics.js` starts at the essence and widens: `punch` and `analogy`, then `steps` (3D, one lead element per step), `quiz`, `faults` (decision trees: every option leads to a node, leaves have `leaf`, `fix`, `pr`, optional `go`), and `math` (MathML via the `MM` helpers, numbers added to `VERIFY`). `tests/topics_audit.mjs` walks every leaf.

## Structure rule
Every topic has an `ARCH` entry in `src/70-structure.js`: `why`, `f3` (CEO, architect, engineer), `blocks` (int, if = interface, ext = other system, with x, y), `flows` (from, to, signal kind e/d/m/o/p, label, the steps where it is active), and `rev` (for every block: what breaks, the first failing step, and an optional simulation preset). Every step must have an active flow and every block a flow; `tests/topics_audit.mjs` checks it.

## Learning model rule
Every topic follows the levels in `src/67-topic-levels.js`: map (where in the machine), essence (steps with `pred` predictions), intuition (`quiz`), engineering depth (`explain` self-explanation), faults (each with `solo` observations and its answer leaf, shown worked, guided and on your own), math (optional), integration (`integ`, linking other topics), and review. Each of see, eng and math ends with a `checks` question. Answers feed a Leitner review queue in localStorage (1, 3, 7, 21 days), interleaved across topics.

## Terms rule
Every new English term must be defined (in `TERM_NEW` in `src/58-terms.js`, or in `LEX`), and given a `TERM_LINK` to the page that explains it if there is one. `tests/terms_audit.mjs` fails on any undefined term. English sentences (interview lines, machine messages) get `lang="en"` so they are not glossed.
